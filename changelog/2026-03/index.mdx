## Permissões de leitura e edição de Contas a Receber na API V3 corrigidas

Ao acessar o endpoint de Contas a Receber pela API V3, usuários com permissão de leitura recebiam erro 401. As permissões de leitura e edição estavam configuradas de forma invertida no sistema. O mapeamento foi corrigido e agora cada nível de permissão funciona como esperado.
</Update>

<Update label="Março de 2026" description="API · Financeiro" tags={["API"]}>
## Consulta de Contas a Receber atrasadas pela API V3 corrigida

Ao filtrar Contas a Receber pelo status "atrasada" via API V3, nenhum resultado era retornado. O sistema agora interpreta corretamente esse filtro e retorna as contas em aberto com vencimento anterior à data atual.
</Update>

<Update label="Março de 2026" description="API · NFS-e" tags={["API", "Notas Fiscais"]}>
## API V2 passa a suportar tributos da Reforma Tributária e emissão de NFS-e via E-Notas

Duas melhorias para quem usa a API V2 de notas fiscais: os novos tributos da Reforma Tributária (IBS e CBS) agora são incluídos nas NFS-e criadas pela API, e passou a ser possível emitir e consultar NFS-e de municípios que utilizam integração com E-Notas.
</Update>

<Update label="Março de 2026" description="API · Pedidos" tags={["API"]}>
## API V2 permite informar CPF do consumidor final ao criar pedidos

Ao criar um pedido via API V2, agora é possível incluir o CPF do consumidor final diretamente na requisição, sem precisar cadastrá-lo como cliente. O comportamento é equivalente ao de uma venda no PDV com CPF na nota.

**Ponto de atenção:** O CPF informado só é considerado quando o nome do cliente no pedido for exatamente igual ao nome do consumidor final configurado na conta.
</Update>

<Update label="Março de 2026" description="API · Pedidos" tags={["API"]}>
## API V3 passa a retornar o campo de responsável pelo frete ao listar pedidos

Ao consultar pedidos pela API V3, o campo que indica quem paga o frete não estava sendo retornado. O dado existia internamente, mas não era incluído na resposta. Agora ele é retornado corretamente em todas as consultas de pedidos.
</Update>

## Antecipação Imediata: antecipe recebíveis diretamente ao criar um pedido de venda

A Antecipação Imediata permite marcar uma venda para antecipação já no momento da criação do pedido. A opção é exibida automaticamente quando o pedido cumpre os requisitos:

- Forma de recebimento: Boleto, Duplicata Mercantil ou Personalizada (com ao menos uma parcela nesse formato)
- Uma ou mais parcelas geradas
- Prazo mínimo de 9 dias para recebimento
- Valor total acima de R$ 100,00

As vendas marcadas ficam na tela de **Antecipações Imediatas** com status de acompanhamento. Quando a nota fiscal é emitida e aprovada, você seleciona os itens que deseja antecipar e parte direto para a simulação no módulo de Crédito.

<Update label="Março de 2026" description="Logística · Correios" tags={["Logística", "Expedição"]}>
## Declaração de Conteúdo Eletrônica (DCe) dos Correios disponível no sistema

A partir de 6 de abril de 2026, os Correios exigem a emissão da Declaração de Conteúdo Eletrônica (DCe) para envios sem nota fiscal. O sistema passa a suportar esse documento com as seguintes mudanças:

- Nas configurações dos Correios, há um novo parâmetro **Utiliza declaração de conteúdo**. Com ele desabilitado, o sistema bloqueia o envio de pedidos sem nota e exibe uma mensagem de erro. Com ele habilitado, a DCe é gerada automaticamente.
- Após o envio, o sistema aguarda a confirmação da DCe pelos Correios. Se a geração falhar, você recebe uma orientação para verificar o e-mail da conta cadastrada — os Correios enviam os detalhes do erro por e-mail.
- Para imprimir o DACe (espelho da declaração), novas opções foram adicionadas nas telas de vendas e de expedição, com três formatos disponíveis: **Completa**, **Resumida** ou **Térmica**.

<Update label="Março de 2026" description="Notas Fiscais · Emissão Automática" tags={["Notas Fiscais", "Vendas"]}>
## Regras de emissão automática de nota fiscal por origem e canal de venda

Agora é possível definir regras específicas para emitir notas fiscais automaticamente conforme a origem do pedido — API, integração com e-commerce ou PDV — e, quando a origem for integração, também por canal de venda (Mercado Livre, Shopee, etc.).

- Sem nenhuma regra configurada para uma origem, a nota não é emitida automaticamente para ela.
- É possível ter regras diferentes para cada origem e canal.
- Pedidos do **Amazon Fulfillment (FBA)** continuam sempre emitindo nota automaticamente, independente de qualquer regra.

**Como habilitar:** Acesse **Configurações → Notas Fiscais → Emissão Automática** e adicione as regras por origem desejada.

**Ponto de atenção:** O parâmetro global de emissão automática continua funcionando para origens sem regra específica configurada.
</Update>

<Update label="Março de 2026" description="Produtos · Importação" tags={["Produtos"]}>
## Tipo e classe de produto agora podem ser alterados via importação de planilha

Ao importar uma planilha de produtos, agora é possível alterar o tipo de um produto já cadastrado — de Simples para Kit, por exemplo. Isso facilita a correção em massa de produtos importados com o tipo incorreto.

- A alteração de tipo só é permitida para produtos das classes **Simples** ou **Kit**.
- Produtos do tipo **Variação** ou **Fabricado** não podem ter o tipo alterado via importação.
- Ao converter um Kit para Simples, os componentes vinculados são removidos automaticamente.
- Se o produto já fizer parte da estrutura de outro kit, a alteração é bloqueada.
</Update>
